# Apply a theme

Read `docs/themes/README.md` first: it names the active theme, the file format and where each
part lands in the code. Then read `docs/themes/system.md`, the component system, which holds
token names, looks, motion presets and the component catalogue.

## 1. Pick the theme

- With an argument: use `docs/themes/$ARGUMENTS.md`. If it doesn't exist, list the `.md` files in
  `docs/themes/` other than `README.md` and `system.md`.
- Without one: use the active theme.

Read the whole theme file and look at its `.png`. If the `.png` is missing or older than the `.md`,
render it: `node tools/theme-preview/render.mjs <name>`.

## 2. Validate it against the system

- Schema in the theme header matches the title of `system.md`. If not, stop. That is a system
  replacement and needs an ADR (see system.md).
- The token block defines every token listed in system.md, in both modes for colours. The Looks table
  has every component id. The Motion table has every slot, with an allowed preset.
- Check the contrast rules in system.md for both modes.

Report gaps and contrast failures to the user and agree on fixes before going on.

## 3. Tokens and fonts

- Replace `apps/desktop/src/lib/theme/tokens.css` with the theme's `css` block, verbatim, under:
  `/* Generated by /apply-theme from docs/themes/<name>.md. Do not edit by hand. */`
- Compare the Typography table's `Package` column with the font packages in `apps/desktop/package.json`.
  Then `npm install` / `npm uninstall` (in `apps/desktop`) and update the `@import` lines at the top of
  `apps/desktop/src/app.css`. `system` needs no package.

## 4. Components

For every component in `apps/desktop/src/lib/components/`:

- The root carries the look class from the theme's Looks table (`look-open|soft|float`). Structure
  follows the look's definition in system.md.
- Motion uses the component's `--motion-<slot>` variable and implements the slot's preset.
- No literals anywhere in `apps/desktop/src` outside `tokens.css`:
  ```sh
  grep -rnE '#[0-9a-fA-F]{3,8}([^0-9a-zA-Z_-]|$)|rgba?\(|hsla?\(|[0-9]m?s([^0-9a-zA-Z_-]|$)|font-family:[[:space:]]*[^v[:space:]]|border-radius:[[:space:]]*[0-9]' apps/desktop/src --include='*.svelte' --include='*.css' | grep -v lib/theme/tokens.css
  ```
  Replace each hit with the token the system names. If none fits, ask. Never invent a token.

When building a **new** component, take its id, parts, states, tokens and motion slots from the
catalogue in system.md, and name the file after the id (`ui/sidebar-entry` → `SidebarEntry.svelte`).
If the component isn't in the catalogue, add it there first (system.md, "Extending the system") and
tell the user.

## 5. Record and check

- If the active theme changed, update "Active theme" in `docs/themes/README.md`.
- `cd apps/desktop && npm run check && npm run build`.
- Ask the user to compare `npm run tauri dev` with the picture in dark and light. Light mode:
  `document.documentElement.dataset.theme = 'light'`.
